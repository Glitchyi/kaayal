# Feature spec: Kaayal Phase 1 — Inbound Voice + OpenAI Reply

**Status:** Draft for owner review; implementation authorized only after review prompt and explicit instruction.

## Goal
As a caller, I can dial the already-provisioned Sarvam phone number, talk in Malayalam or English, ask a simple open-ended question, and receive a natural, spoken reply generated by OpenAI through a backend HTTP tool.

## Actors
- **Caller**: talks over ordinary phone call; no website/account required.
- **Sarvam hosted Voice Agent**: answers inbound calls, recognizes caller's speech, orchestrates turns and speaks tool responses.
- **Kaayal FastAPI tool adapter**: validates a tool request and calls OpenAI Responses API.
- **Owner/developer**: configures existing number, tests live behavior, protects credentials.

## Functional requirements
- FR-01: Existing Sarvam number is bound to the Kaayal hosted agent through supported dashboard steps; no new number is procured.
- FR-02: Agent introduces itself as **Kaayal / കായൽ** and can accept Malayalam and English speech, subject to confirmed service support.
- FR-03: Agent uses a configured HTTP tool to send the caller's substantive question to `POST /api/voice/reply`; request includes transcript text and optionally a non-PII correlation ID/language.
- FR-04: Endpoint authenticates tool traffic, rejects invalid or oversized requests, invokes OpenAI Responses API with a server-side key, and returns short, speakable plain text matching official Sarvam response shape.
- FR-05: Agent speaks the returned result aloud. If external tool fails, it admits the temporary limitation without falsely asserting success.
- FR-06: Health endpoint is available for tunnel/deployment smoke checks.
- FR-07: No transcripts, call recordings, caller numbers, or tourism data are persisted by Kaayal in Phase 1.
- FR-08: System prompts prohibit invented pricing, real operator claims, reservation confirmations, and unsupported actions.
- FR-09: Developer can verify an OpenAI-backed turn with an opaque correlation ID and a sanitized request outcome, not merely a generic Sarvam response.

## Non-goals — explicitly deferred
Operator and boat data; itinerary recommendations backed by listings; actions/booking/payment/WhatsApp; human callback queues; after-hours routing; dashboards; database; outgoing calls; custom streaming telephony; P2P; web voice client; Aadhaar/eKYC.

## User story and acceptance
Given the number is active and bound to the configured agent, when I call and ask in Malayalam about what Kaayal can do, the hosted agent calls the FastAPI tool, FastAPI gets an OpenAI reply, and the reply is audible. A second English question also works. The developer confirms a sanitized tool-call trace while no secrets or raw transcripts are logged.

## Risk and mitigation
- Sarvam's hosted agent may not choose a tool on every turn. Require tool usage in agent instructions where supported, validate with actual call traces; if impossible, document the limitation honestly.
- Live tunnel URLs can change. Provide simple redeployment steps and check `/health` first.
- Latency/timeout may interrupt calls. Bound OpenAI output and request timeout, use short spoken fallback.
- Language support varies by model and voice. Test actual Malayalam and English voices; don't advertise unsupported languages.

## Definition of done
One live inbound Malayalam call and one English call where an OpenAI tool invocation is demonstrably made and the agent speaks a useful response. A mocked automated test suite passes. All manual setup instructions are reproducible.
